## 0. 一頁摘要

EarthDex 讓玩家在現實世界拍攝動物，經 AI／防作弊驗證與物種知識問答後，正式解鎖該物種圖鑑及取得一張對應卡牌。卡牌採四方向數值，在 3×3 九宮格中輪流自由放置，比較相鄰方向數值、翻轉敵方卡牌。物種的生態資料與其卡牌定義分離；玩家的圖鑑、實際卡牌持有紀錄、野外觀察與對戰紀錄亦分離。

**遊戲定位 [確認；前五輪（含第五輪）]**
- 起步只做動物，但資料層可以擴充至植物、真菌等類群。
- 先做可玩的展示版；免費、非營利、教育導向。
- **正式持有卡牌僅能從經驗證的野外觀察取得**；AI 與真人對戰只能解鎖圖鑑，不授予對方實體卡牌。
- 單人 AI 和線上 PVP 都在展示版的**目標範圍**內，可分階段實作及驗收。
- 所有物種規格化生成卡牌，同物種同規則版本具有相同數值及技能。

**參考遊戲 [確認為參考，不代表照搬]**：2019 年《主公快出牌》使用九宮格、相鄰比點、翻面、卡牌技能、PVE 與真人對戰。EarthDex 借鏡的是遊戲類型及策略節奏，不複製其美術、角色、品牌、文字、專有技能表或原始程式。資料來源見文末。

## 1. 前五輪確定的玩法與獎勵

### 1.1 野外探索 [確認]
1. 以 App 內建相機記錄野外動物，不以外部圖片直接取代本次野外驗證。
2. AI 辨識物種，並進行影像連續性、GPS、時間、重播／模擬輸入等分級審核。一般物種採較輕驗證，稀有／敏感物種採較嚴審核，必要時人工確認。
3. 玩家通過物種知識**一題選擇題**，才可完成該次符合資格的卡牌收集及圖鑑解鎖。答錯可先學習再回答另一題，**不用重新拍攝**。
4. 重複觀察同種動物可產生新的觀察紀錄；是否給新卡須再通過 GPS／時間／防作弊規則。
5. 不應要求接近、追趕、捕捉、騷擾或觸碰野生動物；可採遠距攝影與補審。

### 1.2 卡牌與牌組 [確認]
- 每一物種對應一種官方卡牌定義；玩家可以持有多個該物種的**卡牌實例**。
- 每張牌有上、右、下、左四方向戰鬥數值及**一個**特殊技能。
- 四方向僅是抽象戰鬥數值，不對應固定的攻擊、敏捷、防禦等生物學意義。
- 同物種、同官方規則版本的四方向與技能相同；固定亂數種子提供可重現的選擇。
- 四方向數值與技能成本共用統一點數預算；技能須由有來源的生態特徵標籤過濾，再以固定種子從合格技能中抽選。
- 生態資料不足者產生中性數值、通用技能，不捏造特徵。
- 每副牌組**5 張**，**同一物種最多 2 張**；至少須有**3 種不同物種**才能組成 5 張合法牌組。
- 玩家需先真正取得 5 張合法卡牌才能參與對戰；不提供新手借用牌組。
- 卡牌無法旋轉，四方向永遠固定。
- 官方平衡版本更新時，同物種的所有現有卡牌同步改用新版能力；對戰重播保留當時版本。

### 1.3 九宮格對戰 [確認]
1. 3×3、共 9 個空格，雙方每人帶入 5 張卡牌。
2. 雙方交替放一張牌於**任意未佔據的格子**；不限定己方半場、不固定放置位置。
3. 先手放 5 張、後手放 4 張；後手第 5 張留在手牌。先後手公平性**先不改規則**，正式以可重現策略模擬決定是否調整。
4. 新放的卡牌只與上下左右相鄰的**敵方控制卡牌**比較，且僅在新的方向值**嚴格大於**對應方向值時可翻轉（不含技能修正）。相等不翻。
5. 同一次放牌的所有相鄰基本比較先計算完，之後**統一執行翻轉**，再處理翻轉後技能。
6. 普通翻轉本身不會引起連鎖；只有具明確效果的技能可以連鎖。
7. 技能引發的連鎖每次放牌**最多 3 層**（一層的精確定義仍待確認）。
8. 9 格填滿後，最後**控制格數較多者獲勝**。在全部格子皆為紅／藍的前提下沒有平手；若將來出現中立／空白格則需重訂。
9. 被翻轉的卡牌，**技能控制權改為新陣營**。已消耗技能次數是否恢復，**依技能定義**。
10. 同種技能或多張牌加成可疊加，但**依技能類型**設上限。
11. 抵抗／防禦技能在「原本的比較會造成翻轉」後才觸發，先抵抗再正式改變陣營。
12. 展示版不支援技能造成位置移動或交換；技能暫時限定數值、翻轉、抵抗及相關效果。

### 1.4 單人、PVP、圖鑑 [確認]
- 單人 AI 與線上 PVP 共用**完全相同的對戰判定引擎**，AI 只影響選牌與放置決策。
- AI 牌組依主題、地區、難度挑選；**單人 AI 和 PVP 都能透過對戰解鎖物種圖鑑**。
- 玩家於對戰結束時，若**仍控制**一張先前不認識的對方物種卡，即取得其圖鑑解鎖問答資格；若中途翻回敵方則不算。
- 一局涉及多個新物種時，**每個物種各回答一題**，各自決定是否解鎖；玩家**不獲得**對方卡牌。
- 圖鑑由多個重疊系列組成（國家、緯度、生態區、分布特徵、動物園等）；任何管道正式解鎖物種均可更新其適用系列，完成系列獲徽章／稱號等**收藏型獎勵**。
- 動物園參觀可提供經授權的場館認證、徽章與物種紀錄，**不得直接授予正式卡牌**。動物園紀錄是否直接視為「正式圖鑑解鎖」仍待決。

### 1.5 GPS 重複卡牌 [確認原則／待決精確語義]
- 同地點可以蒐集**不同物種**；重複限制僅針對「同一玩家＋同一物種」。
- 玩家最新選擇：新卡要同時滿足**距離至少 1 km**以及**時間相隔至少 7 天**；距離比對範圍選的是**過去 7 天內所有成功領取該物種卡牌的地點**。
- **重要邏輯衝突 [待決]**：若「最近一次領卡後至少 7 天」是全域必要條件，那麼到了允許領卡時，最近 7 天內通常沒有領卡紀錄；拿「最近 7 天所有地點」比距離會變成空集合，距離門檻幾乎不生效。必須重訂**時間參考點與空集合處理**，不能自行假設。
- 暫時**不可將 GPS 規則實作為正式發獎判定**，直到問題 Q1–Q3 解決；仍可先實作觀察地點保存、精度檢查與距離計算。


### 1.6 影像驗證與審核 [原始企劃方向；參數待決]
- 使用 App 內錄影而不是接受外部相簿／網路影片直接作為新野外發卡證據；可以附帶環境先廣角、目標放大、再退回環境的同段連續錄影。
- 可在同段錄影中要求玩家完成**隨機手勢／挑戰**，提高使用預錄素材作弊的難度，但手勢本身不是不可偽造的真實性證明。
- 以影片連續性、光影／重播異常、螢幕或投影跡象、時間、裝置位置精度、反覆投稿等**多信號**決定可信度；不以單一螢幕矩形輪廓作為絕對真偽判定。
- AI 辨識應有類別不確定／信心不足結果，並允許玩家申請人工覆核。建議狀態包含 `submitted`、`ai_reviewed`、`manual_review`、`verified`、`rejected`、`appealed`（實際狀態名稱待定）。
- 稀有物種的精確地點與照片中可識別的地標需保護；不可為了挑戰要求靠近、驚擾動物，也不能把不同棲地的保育風險一視同仁。
- 驗證成本：先以有限物種／地區建立影片、GPS、題庫、人工審核流程；不要承諾展示版能覆蓋所有動物。

## 2. 技能與事件引擎：已確認部分和候選執行流程

### 2.1 引擎要求 [確認]
- 確定性：相同對局初始狀態、同規則版本、同一操作序列，結果相同。
- 單人與線上共用引擎；線上以伺服器為權威來源，前端只發送合法動作意圖。
- 分離**不可變卡牌定義**、**玩家持有卡牌實例**、**對戰場上卡牌狀態**。
- 每個技能有明確觸發事件、效果種類、作用對象、優先權、疊加規則、限額、重置規則、持續時間與版本。
- 同一次放牌最多 3 層技能連鎖，並記錄事件軌跡；不得形成無窮迴圈。

### 2.2 建議事件階段 [提案，尚待核准]

```text
ValidateMove
  -> PlaceCard
  -> OnPlacedEffects
  -> BuildBaseComparisons (以同一戰場快照計算四鄰)
  -> ApplyComparisonModifiers (分類上限)
  -> SelectTentativeFlips
  -> ApplyResistEffects (只對原本會翻牌者)
  -> CommitFlipsSimultaneously
  -> OnFlippedEffects (控制權已改變)
  -> SkillChainLayer1
  -> SkillChainLayer2
  -> SkillChainLayer3
  -> EndTurn / EndMatch
```

**注意**：技能是否能在基本比較前發動、同時觸發如何定序、「3 層」是否含第一次技能效果、翻牌後場上持續光環何時重算，都**尚未定案**。此流程不能視為正式遊戲規則。

### 2.3 技能資料模型 [提案]

```yaml
skill_id: ARMOR_001
version: 1
eligible_trait_tags: [ARMOR]
trigger_phase: BeforeFlip
activation_rule: once_per_match
cost: 6                 # 假設示例；尚未平衡核定
limit_reset_on_flip: false  # 每個技能需明確設定
stack_group: flip_resist
stack_cap: 1
chain_generation: none
effect: cancel_one_eligible_flip
```

- 範例技能：群體合作（相鄰友軍方向加成）、伏擊（條件加成）、偽裝（防禦修正）、裝甲（抵抗翻轉）、毒性（翻轉後影響鄰牌）、再生（被翻轉後產生效果）。
- **不宣稱**這些是各物種的科學量化能力；必須先有可信生態標籤，再將生態特徵轉換成平衡設計。

### 2.4 數值生成 [提案]

`總預算 B = 上 U + 右 R + 下 D + 左 L + 技能成本 C_skill`

展示版可先測 `B=28`、每方向 `[1,10]`，**皆為示例而非已決定數值**。有效技能池依 `species_id + generator_version + trait_snapshot_version` 建立固定排序後，以固定種子選技能；再依穩定權重與預算分配方向數值。卡牌一經發布，需保存數值、技能、輸入版本與演算法版本。資料缺漏時選中性卡和通用技能，不讓 LLM 在缺證據時臆測特徵。

## 3. 核心資料庫：邏輯實體與分離原則

> 僅是邏輯資料模型；欄位、索引及資料型別需在落地階段建立遷移規格。

| 資料表 / 實體 | 主鍵與重要欄位 | 用途 |
|---|---|---|
| `species` | `species_id`、accepted_name、rank、taxonomy_status | EarthDex 的穩定物種實體；不以學名作唯一 ID |
| `taxon_external_ids` | `species_id`、source、external_id、source_version | COL、GBIF 等外部分類對映 |
| `taxon_names` | `species_id`、locale、name、is_preferred | 多語名、俗名、同物異名 |

| `species_regions` | `species_id`、region_id、occurrence_type、evidence_version | 分布與國家／棲地分類；區分原生、遷入等 |
| `media_assets` | `species_id`、uri、author、license、attribution、consent_status | 圖片授權、出處、可用性 |

| `card_instances` | `card_instance_id`、player_id、species_id、source_observation_id、grant_id、issued_at | 物理意義的遊戲持有卡牌；不包含對戰翻轉所得卡 |
| `dex_unlocks` | `player_id`、species_id、method、unlocked_at、quiz_result_id | 同物種正式圖鑑一筆、可記多來源事件 |
| `dex_series` / `dex_memberships` | `series_id`、`species_id`、taxonomy_version | 多維分類與進度計算 |
| `observations` | `observation_id`、player_id、species_id、media_id、location_secure、accuracy、verified_at、status | 野外觀察與證據；座標需保護 |
| `reward_grants` | `grant_id`、observation_id、player_id、species_id、rule_version、granted_at | 可重試且防重複的正式領卡紀錄 |
| `quiz_items` / `quiz_attempts` | `question_id`、species_id、source_ref、attempt_id、is_correct | 物種教學、回答與解鎖證明 |
| `matches` / `match_events` | `match_id`、mode、rule_version、seed、event_seq、hash | 對局狀態與可重播事件日誌 |

| `review_cases` | `case_id`、observation_id、status、decision_reason | 人工辨識和防作弊申訴 |
| `zoo_visits` / `badges` | `visit_id`、venue_id、proof_type、badge_id | 園區認證與徽章，不核發野外正式卡 |

**一致性規則**：
- `card_instances` 必須有合法獲卡來源與唯一 `grant_id`；同一觀察不能重複發卡。
- `dex_unlocks` 與 `card_instances` 不可互相推定；圖鑑解鎖 ≠ 持有卡牌。
- 玩家在對戰中翻牌只變更 `match_events`／場上控制者，**不移轉 `card_instances.owner_id`**。
- `species_id` 不應因學名更名而變更；拆種、合種需有人工／資料維護策略。
- 物種圖鑑系列成員可能隨分類更新而變更，需保留已取得歷史與版控。

## 4. 全球資料與資料來源策略

**初始候選**（各資料需個別確認授權與可用欄位）：
1. **Catalogue of Life（COL）**：物種分類／學名與版本基準。2026-10 Base 約 227.7 萬物種，Extended 約 250.5 萬；全球全生物類群，不代表都有完整照片、生態與 AI 模型。<https://www.catalogueoflife.org/data/download>
2. **GBIF**：全球物種出現紀錄與分布參考，須處理誤判、坐標模糊與個別資料集授權。<https://www.gbif.org/>
3. **Encyclopedia of Life / TraitBank**：可評估作為附來源生態特徵資料，實際覆蓋率需測試。<https://eol.org/>
4. **iNaturalist**：協助觀察與保育座標隱私機制的參考；照片、資料使用權限和座標保護需要逐項確認。<https://help.inaturalist.org/en/support/solutions/articles/151000233080-how-does-inaturalist-protect-the-locations-of-sensitive-species->

**授權原則**：免費／非營利不等於所有圖片與 API 均可無限制使用；照片著作權、署名義務、商業使用條件與再散布條件要逐資產記錄。稀有物種與玩家的精確位置不得公開，避免濫用。

## 5. 玩家體驗流程（目標）

**野外探索**：首頁 → 探索相機 → AI 初辨 → 真實性／地點／保育檢查 → 必要時人工審核 → 物種介紹 → 一題問答 → 觀察存檔 → 若符合獎勵條件則發卡＋正式圖鑑解鎖 → 更新所有對應系列。

**對戰**：卡牌收藏（持有至少 5 張且合法組牌） → 選擇 AI 或 PVP → 5 張牌進場 → 9 次交替放牌 → 逐回合計算比點、抵抗、同時翻轉、最多 3 層技能連鎖 → 結算控制格數 → 確認玩家最終控制且未解鎖的物種 → 每物種各一題問答 → 答對者解鎖圖鑑／更新系列。

**特殊情境**：辨識不確定、影像不合格、網路中斷、問答答錯、GPS 訊號不準、物種合併改名、PVP 斷線、牌組版本更新，均須有可恢復狀態與錯誤處理。

## 6. 展示版技術方案 [提案]

- **手機端**：Flutter + Flame（地圖／相機／圖鑑介面與 2D 卡牌互動）；若先驗證規則，可另做 TypeScript 網頁戰鬥原型。
- **遊戲規則核心**：與 UI 分離的純函式／狀態機；單人 AI、客戶端預覽與伺服器共用同一演算法規格及測試向量。初步考慮 TypeScript 或 Rust 的可共用核心；具體語言仍需決策。
- **後端**：FastAPI（Python），PVP 使用伺服器權威判定；WebSocket 或等效雙向通道需視部署決定。
- **資料層**：PostgreSQL；地理查詢可用 PostGIS；影片與照片放物件儲存，資料庫只存安全存取索引。
- **AI 辨識**：採有限覆蓋動物分類模型、信心門檻、地區分布合理性與人工審核。不能假設展示版即可準確辨識全球數百萬種生物。
- **安全與隱私**：最小化地點與影片保留、分級審核、加密存取、敏感物種模糊座標、可刪除個人觀察與公開資料隔離。

## 8. 自動化測試與驗收規格

**必測案例**：
- 新牌右值 `7` 對右鄰敵牌左值 `5` → 成功翻牌；`5` 對 `5` → 不翻。
- 新牌一次與上、右兩張敵牌相鄰 → 在同一初始快照判定兩者，再統一翻牌。
- 普通翻牌不造成額外鄰卡連鎖；技能產生連鎖至第 3 層後停止。
- 已觸發抵抗技能且符合該技能限額規則時，該次原本成功的翻牌被阻止。
- 卡牌翻轉後技能控制者改變；使用次數是否重置由該 `skill_id` 規範決定。
- 相同物種固定版本數值、技能完全一致；任意亂數種子序列不會超出預算／數值邊界。
- 同種最多 2 張、牌組必有 5 張；3 種物種是滿足合法牌組的最少物種數。
- 9 格填滿 → 控制格多者贏，單人與伺服器對相同動作給相同結果。
- 玩家沒有實際擁有的敵方卡牌，對戰結束仍控制且答對題目 → 只增加圖鑑，不產生卡牌實例。
- 同物種重複觀察成功但獎勵資格不符 → 留觀察紀錄，不新增卡牌。
- 同一觀察因網路重送／重試的領卡請求只發出一次獎勵（交易原子性、冪等性）。
- 位置及保育敏感欄位不在公開 API 或分享頁外洩。

**公平性**：需要帶程式碼、固定種子、策略配置、樣本量、置信區間的可重現模擬。之前對話提過的「先手 71.37%」未附可查驗的模擬程式與原始數據，不應視為正式證據，也不應據此調整規則。

## 9. 全部待確認問題（可一次回答）

### A. GPS 與收集機制（高優先）
1. **GPS 核心邏輯**：維持「7 天 AND 1 km」時，距離究竟與**最近一次領卡紀錄**、**歷史所有領卡紀錄**，或**最近 7 天所有領卡紀錄（空集合時如何處理）**比較？如果希望同地 7 天後可以再領卡，與目前 AND 規則不同，請明確選擇。
2. 「7 天」是距離同物種**上一張成功領卡的時間**，還是與**欲比較之每筆紀錄**個別計算？以 168 小時或日曆 7 天計？
3. 距離達 1 km 的比較標準：直線球面距離（建議）、道路距離或行政區？GPS 精度太差時採拒絕、重新定位或人工審核？
4. 在同一地點再次拍攝不同物種，可各自獲卡已確認；若同一物種在觀察核准時資料庫更名／拆種，獎勵如何歸屬？

7. 同層多個技能同時觸發時依**同時快照→一起結算**、**先進先出事件佇列**或**技能優先權**判定？若互相矛盾，哪個優先？

9. 各類技能疊加上限是多少（方向數值加成、抵抗次數、連鎖效果）？臨時數值可否突破卡面數值上限？
