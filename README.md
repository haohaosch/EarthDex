# EarthDex · Field Adventure v0.2

繁體中文的臺灣生物探索與九宮格卡牌遊戲。最新使用者指示優先於原始 v0.6 草案：現在拍照比對後，直接採用分數最高的候選物種，再答對一道物種問題才收入卡牌；沒有信心門檻或人工審核，卡牌在答對時隨機生成。

## 本機執行

Node 24：`npm ci` → `npm run dev`，開啟終端顯示的網址。相機需要 HTTPS 或 localhost。`npm test` 驗證引擎、收集與伺服器；`npm run build` 進行 TypeScript 檢查及正式建置。產出自含前端資產的 `dist/server/index.js` Cloudflare Worker。

資料存在本機忽略版控的 `.sites-runtime/`；正式環境使用 `DB` D1 與 `BUCKET` R2。Drizzle 結構遷移位於 `drizzle/`。不要把私人觀察、權杖、模型權重或執行期資料提交至 Git。

## 拍照 → 辨識 → 收集

1. 內建相機拍下單張 JPEG，預覽、重拍；不接受相簿輸入。
2. 裝置端 BioCLIP ViT-B/16（FP16 權重、FP32 運算） 視覺編碼器擷取 512 維影像特徵。伺服器以臺灣動物的影像參考庫與物種名稱特徵比對，回傳物種、相似度及候選。分數不是校準過的正確率。
3. 不論分數高低或前兩名分數是否接近，一律採用支援物種中排名第一的候選；同分時以固定物種 ID 排序，保持結果可重現。
4. 伺服器先保存照片觀察，再提供該物種問答；答對才生成卡牌與解鎖圖鑑，答錯可閱讀說明後換題。題目版本由伺服器驗證。
5. 未收集物種可先查看可能技能的說明，四方向點數維持問號。收集時才抽出實際技能與方向值，保存為實例快照，再以翻牌動畫揭曉；翻牌是展示效果，不是領取條件。
6. 同一觀察重送只領一次；相同照片 SHA-256 在同一玩家檔案內不重複建立觀察。所有權、圖鑑與戰場控制者保持分離。

首次辨識需要下載約 165 MiB 的公開 MIT 模型，瀏覽器會嘗試快取。新版更換為 WebAssembly 可執行的模型匯出，會自動移除舊版模型快取。模型在使用者裝置運算，照片不送至 Hugging Face 或第三方推論 API；下載程式與權重需要可連線至 jsDelivr 與 Hugging Face。模型推論與首次載入時間依裝置、網路而異。辨識照片只存入該玩家的私人觀察空間，可查看與刪除。

## 物種與辨識範圍

82 筆物種／分類單元，其中 81 筆為臺灣可見動物（都市、公園、農地、山林、濕地、海岸、常見飼養／外來動物），另保留舊版小貓熊資料以相容已存對局。不是只收錄特有種，也不是臺灣完整名錄。臺灣鹿與黑熊的名稱含亞種；目前為遊戲分類單元，未實作完整分類學 ETL。

參考庫的實際支援數、公開照片數與小型測試結果見 `docs/recognition-evaluation.json`。未完成參考照片的分類單元仍可瀏覽圖鑑，但不被當作已支援的識別類別。Wikimedia 圖片作者、授權與來源保存在 `src/media.json`；模型參考照片及其授權列於 `engine/recognition/reference-bank.json`。

## 模型建立與誠實限制

這是自己建立的臺灣物種比對分類器，搭配現成 BioCLIP 編碼器，**不是從零訓練通用視覺基礎模型**。BioCLIP 出自 Imageomics Institute（Stevens 等，CVPR 2024，MIT）。影像與文字的相容 ONNX 轉換由 Trail Bingo 提供（FP16 權重、FP32 運算）；權重固定到特定 Hugging Face commit。模型與程式來源、方法與評估細節見 [模型說明](docs/MODEL.md)。

`build-reference-library.py` 蒐集有授權的公有圖片，`build-text-prototypes.py` 產生名稱向量，`train-recognizer.py` 建立參考庫並執行小型留出測試。測試照片不是使用者真實野外樣本，不能將結果宣稱為一般使用準確率。相似種、幼體、遮擋、拍攝角度及背景都可能影響辨識。

瀏覽器回傳的特徵不能證明照片真實性，亦不能阻止被修改的客戶端作弊。這版依使用者要求採即時識別與遊戲收集，不宣稱已完成野外防作弊驗證。原草案中未定案的 GPS 1 km / 7 天條件未套用。正式的反作弊、裝置驗證、座標規則、稽核與大規模營運仍是後續工作。

## 卡牌與對戰

5 張實際持有卡牌，每種最多 2 張、至少 3 種；無借用牌組。3×3 自由落牌、不可旋轉、嚴格大於才翻牌；同一波快照比較後同時翻轉，普通翻牌不連鎖。技能最多額外 3 波。9 格填滿後以控制格數判勝。AI 與 PVP 使用同一引擎，伺服器驗證操作及版本。PVP 使用兩秒輪詢，可重新連線，必須有網站存取權；本機兩個獨立瀏覽器工作階段可測試。

對戰仍只授予圖鑑問答資格，不授予／轉移卡牌。重播保存當時實例定義。`capture-0.3` 採 28 點總預算、各方向 1–10，技能成本與方向共用預算。均勻抽選合法方向組合，最大與最小方向至少差 3 點，避免平均配點。技能條件仍以有來源的特徵標籤過濾，缺少特徵時使用中性技能。

舊收藏中四方向全同的卡牌會調整一次，保留技能、卡牌身分與原配置紀錄；其餘卡牌維持原能力。已開始的對局與重播使用原快照。新收集的卡牌一律使用獨立隨機快照。

對戰時，點擊場上任一陣營的卡牌或自己的手牌，可開啟技能視窗，查看技能說明、觸發時機及剩餘使用次數。輪到對手也可查看自己的手牌；輪到自己時在視窗選為出牌，再點空格落牌。

瀏覽器推論相容性檢查：先準備固定版本模型（`python scripts/download-vision-model.py`）及 Python Pillow/NumPy，再執行 `npm run test:wasm`。此檢查使用與網站同版的 ONNX Runtime Web 1.22.0 WASM provider，實際將公開海龜照片轉成特徵並確認辨識為綠蠵龜；不是以 Python CPU provider 代替。報告見 `docs/wasm-recognition-check.json`。

戰報與技能視窗的比點紀錄會顯示基礎方向值、技能加成與實際比較值。加成取自該次結算紀錄，不以目前鄰牌重算，因此後續翻面不會改寫歷史結果。獼猴群聚占 4 點預算（方向合計 24），鄰接友軍每張 +1、最多 +2；藍鵲上 6 對獼猴下 5＋群聚 2＝7 時不會翻面。
